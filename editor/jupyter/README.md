# Eqiora notebook editor

This prebuilt Jupyter extension highlights `%%eqiora` source cells using the
[canonical TextMate grammar](../eqiora/syntaxes/eqiora.tmLanguage.json). A small
CodeMirror adapter maps TextMate scopes to editor styles. It does no semantic
parsing, keeps no vocabulary of its own, and never executes source.

The header selects Eqiora for that cell; removing the header restores the host
language. Selection follows the current source, including before execution and
when reopening a saved notebook. Ordinary Python cells retain their language.
Markdown and Raw cells retain their languages even with a magic-looking header.
Types and units use the host's builtin color. No notebook metadata is changed.

The Python kernel also needs `%load_ext eqiora.jupyter` from the same development
revision. If the Jupyter server and the kernel run in different environments,
install the frontend assets in the **Jupyter server environment** and Eqiora in
the **kernel environment**. This feature is not in the published Eqiora 0.1.2
package. Colab and VS Code notebooks do not load this plugin.

Completion comes from the optional Python extension through the shared native
editor service, not from this syntax adapter. Hover sends the current cell to its
kernel over a short-lived Comm and shows the compiler's declaration, type,
documentation, and notation details as plain text. It needs an idle kernel with
the extension loaded, never executes the cell, and discards replies that arrive
after an edit, a kernel change or restart, a disconnection, or closing the editor.
Requests are limited to 256 KiB of cell source, responses to 4096 Unicode code
points, and waiting to three seconds. Hover sees only the current cell: other
cells, Python variables, and external packages are not included, and there is no
Shift-Tab inspection. Python inspection is handled by the kernel as usual.

## Build and inspect

From this directory, with the repository's Node/npm toolchain:

```bash
uv venv .venv --python 3.13
uv pip install --python .venv/bin/python jupyterlab==4.5.11 notebook==7.5.6
export PATH="$PWD/.venv/bin:$PATH"
npm ci --ignore-scripts
npm run typecheck
npm run build
```

The build copies the canonical grammar into an ignored temporary source file.
It writes a single prebuilt output under
`wheel-data/data/share/jupyter/labextensions/@eqiora/jupyter/`, including dependency
licenses. These generated files are checked in for Python packaging: ordinary
package installation must not invoke Node or fetch frontend dependencies.
Rebuild and commit this output after changes to the adapter, grammar or build inputs.
Webpack uses named module IDs so build paths do not change the generated bytes.
From the repository root, `python tools/editor/check_jupyter.py` rebuilds with the
locked dependencies in scratch and checks every shipped asset against that build.
Root Python packaging owns installing the files into `sys.prefix/share/jupyter`.

For frontend development without rebuilding the Python wheel, copy the prebuilt
output into this isolated environment:

```bash
python - <<'PY'
import shutil
import sys
from pathlib import Path
source = Path('wheel-data/data/share/jupyter/labextensions/@eqiora/jupyter')
target = Path(sys.prefix) / 'share/jupyter/labextensions/@eqiora/jupyter'
shutil.copytree(source, target, dirs_exist_ok=True)
PY
jupyter labextension list
python example.py
JUPYTER_CONFIG_DIR="$PWD/.jupyter-test/config" JUPYTER_DATA_DIR="$PWD/.jupyter-test/data" JUPYTER_RUNTIME_DIR="$PWD/.jupyter-test/runtime" jupyter lab --no-browser --ServerApp.ip=127.0.0.1 --ServerApp.port=18927 --ServerApp.port_retries=0 --FileContentsManager.delete_to_trash=False --IdentityProvider.token=eqiora-test --ServerApp.root_dir="$PWD"
```

Open `decay.ipynb` under `/lab/tree/decay.ipynb` or `/notebooks/decay.ipynb`.
`example.py` generates its source cell directly from `examples/decay.eqi`; it
contains no second equation definition. The final Python cell uses the compiled
Model. Execution requires a development Eqiora package in that kernel; editor
highlighting is available before any cell runs.

## Focused checks

```bash
python -m unittest discover -s tests -p 'test_*.py'
npm run typecheck
npx playwright install chromium
npm test
```

With the server above running, use another terminal:

```bash
EQIORA_JUPYTER_URL=http://127.0.0.1:18927 EQIORA_JUPYTER_TOKEN=eqiora-test npm run test:host
```

Tests create temporary notebooks and delete them afterwards. The browser tests
cover keywords, types, units, numbers, and comments; cells that have not been
run; editing the header and switching back to Python; leaving Markdown and Raw
cells alone; reopening saved notebooks; and unchanged execution counts. A separate
host check loads the IPython extension and completes a local name in a cell that
has not been run. The hover checks cover a kernel without the extension, edits to
the current source, Unicode positions, and an unexecuted cell; the adapter unit
tests also cover late replies, restarts, and plain-text rendering. The
mixed-example host check runs all cells, restarts the kernel, runs them again, and
then checks that a failed compilation keeps the previous Model and that corrected
source runs. It also checks the new kernel process and the saved execution counts
in both frontends.

These checks passed on Linux x86_64 with Chromium 151.0.7922.34
(Playwright 1.62.1), JupyterLab 4.5.11, Notebook 7.5.6, IPython 9.17.1, and
ipykernel 7.3.0. The hover host checks used an installed source-built wheel whose
seven frontend files matched the generated assets byte for byte. The isolated
Python package gate checks wheel delivery and the native adapter separately, and
`bindings/python/tests/test_jupyter.py` covers notebook execution. The frontend
tests do not cover Colab's Restart and Run All.

## Locked dependency security updates

The build uses scoped npm overrides for `@jupyterlab/apputils` →
`sanitize-html` 2.18.1 and Mermaid 11 → KaTeX 0.18.11. These intentionally exceed
apputils' `~2.12.1` sanitizer range and Mermaid's `^0.16.47` math range to include
the upstream security fixes. The sanitizer update also removes `deepmerge`.
The repository's Node 24 toolchain satisfies the sanitizer's Node 22.12 minimum.

The [KaTeX 0.18 migration](https://github.com/KaTeX/KaTeX/releases/tag/v0.18.0)
changes internal CSS classes; Mermaid uses the public `renderToString` API rather
than KaTeX's changed internal function-definition API. Focused browser tests cover
Jupyter's sanitizer, MermaidManager's native-MathML fraction rendering, HTML math
with the matching KaTeX stylesheet, and
[inherited-trust hardening](https://github.com/KaTeX/KaTeX/security/advisories/GHSA-238p-pmpm-9mq7).
These checks support this locked consumer combination, not every Mermaid option
or a pixel-equivalence claim. Revisit the overrides when the upstream consumer
ranges include patched releases.

These pins cover this extension's npm build tree. The prebuilt extension consumes
Jupyter-provided shared modules; changing this lock does not replace a separately
installed JupyterLab host's static assets or dependencies. Host integration tests
check the editor extension in that host, not whether the host's own sanitizer or
math packages have been upgraded.
