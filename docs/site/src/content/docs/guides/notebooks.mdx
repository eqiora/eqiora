The current development package provides an opt-in IPython extension. It is
not included in the published Eqiora `0.1.2` package. Use the
[development installation](/get-started/#development-build) when trying it.
Ordinary Python scripts continue to use `eqiora.compile` directly.

## Select your Python environment

Use a Python kernel from the environment containing Eqiora. For a local
JupyterLab environment, install the notebook tools into that same uv project:

```bash
uv add --dev jupyterlab==4.5.11 ipykernel
uv run jupyter lab
```

In a Python cell, load the extension explicitly:

```python
%load_ext eqiora.jupyter
import eqiora
```

## Compile a source cell

Create another code cell with this content:

<Code code={`%%eqiora model\n${modelSource}`} lang="eqiora" />

After successful execution, `model` is the ordinary compiled `eqiora.Model` in
the shared Python namespace. Continue with the configuration and execution
steps from [Run and inspect](/guides/run-and-inspect/), using this `model` in
place of that guide's `eqiora.compile(...)` call. Editing the cell has no effect
on a compiled Model until you execute the cell again.

Compilation errors retain the native diagnostic codes and source spans. Notes
show the notebook cell's line and column, counting the `%%eqiora` header as
line 1. A failed re-execution preserves the last successful `model`; correct
the source and rerun the cell before continuing your numerical investigation.

## Supply ordinary compiler inputs

The magic accepts these optional arguments:

```text
%%eqiora model --entry SelectedModel --bindings inputs --geometry geometry
```

`SelectedModel` is a declaration name. `inputs` and `geometry` are names of
existing Python variables containing the same bindings and Geometry accepted
by [`eqiora.compile`](/reference/python/eqiora/). Supply only the options your
source needs. Variable names are single Python identifiers; the extension does
not evaluate Python expressions in the header or interpolate the Eqiora body.

## Frontend support

The development package includes a prebuilt editor extension for JupyterLab
4.5.11 and Notebook 7.5.6. A code cell beginning with `%%eqiora` uses the same
syntax grammar as `.eqi` files, before execution and after reopening the notebook.
Removing the header restores the ordinary Python editor. After loading the
IPython extension, request completion at the end of a name prefix with Tab,
then select a candidate and press Enter.
The current source cell uses the same contextual vocabulary and visible
declarations as the native editor service, including incomplete source.
Completion neither executes the cell nor changes its Python variable. Ordinary
Python cells keep Python completion.

This is standalone source-cell completion: Python variables, other cells and
external package imports do not become Eqiora declarations. Completion inside
an existing token is omitted because the IPython matcher only replaces text
before the cursor. Notebook hover is not yet provided. Installed-package matcher
tests used IPython 9.17.0; notebook host checks used IPython 9.17.1 and
ipykernel 7.3.0.

Install Eqiora into the environment that runs the **Jupyter server** as well as
the Python kernel if those are separate. Restart the server after installing
or updating the extension; `uv run jupyter labextension list` should list
`@eqiora/jupyter`. The frontend does not need a Node.js build during installation.

The editor was exercised on Linux x86-64 with the versions above. VS Code
notebooks and Colab do not load this Jupyter extension; their highlighting and
Colab Restart and Run All are not claimed by these checks.

If `%load_ext` reports that `eqiora.jupyter` is absent, check the kernel's
`eqiora.__file__` and package version: a different environment or the published
0.1.2 package will not contain this development feature. Loading Eqiora in a
normal Python process does not load IPython. `%unload_ext eqiora.jupyter`
removes the magic and leaves existing compiled Models available.
