## 0.1.0a13 — constraints, trajectory sensitivities, and shared regions

[Eqiora 0.1.0a13](https://github.com/nkiyohara/eqiora/releases/tag/v0.1.0a13)
adds finite equality/inequality/complementarity execution, event-aware ODE
Parameter JVPs, fixed-volume conservation storage, and exact Field recovery for
complete Cartesian scalar Region chains. The maintained Python property specimen
also executes and replays offline from one exact local package lock.

Named component-owned test functions and `weak_form` replace `primal_form` and
the global `test(field)` helper. Rust language consumers use
`RelationCondition`; the former `Equation` and `LexResult` exports are removed.
Regenerate pre-1.0 Models and saved artifacts for Model/Transaction v27, Source
identity v19, structural fingerprint v22, Plan/Result v5, and Trajectory v3.

Storage remains short of transient spatial thermal execution. Plural scalar
regions remain short of mixed/vector execution, arbitrary geometry, viewer
blocks, and solver-owned block/quotient structure.

## 0.1.0a11 — exact imported nominal types

[Eqiora 0.1.0a11](https://github.com/nkiyohara/eqiora/releases/tag/v0.1.0a11)
adds `ModuleRef.record`, `ModuleRef.enum`, and `ModuleRef.space` to Python
authoring. Independent components can use public nominal types from an explicit
Module import while emitted source preserves the qualified provider path.

The existing Module resolver remains authoritative for visibility, nominal
identity, member typing, source locations, and exact locked-package resolution.
Private, unknown, transitive, and equal-shaped foreign declarations reject, and
provider definitions are not copied into the consumer. Imported Record
descriptors remain distinct from locally owned Records while sharing nominal
construction behavior.

## 0.1.0a9 — structured execution profiling

[Eqiora 0.1.0a9](https://github.com/nkiyohara/eqiora/releases/tag/v0.1.0a9)
adds opt-in `profile=True` execution to Python. Results retain an immutable,
hierarchical timing profile across run, setup, solve, time-step, assembly,
nonlinear-iteration, linear-solve, backend, and post-processing phases, together
with structured nonlinear convergence observations. The transient cylinder
example can print a compact summary from the same profile.

Profiling is disabled by default and disabled runs retain identical numerical
result bits without installing a collector. Timings cover the current process;
profiles are not serialized with Results and do not claim distributed or global
timing coverage. This alpha covers common flow paths, ODE execution, Newton
iteration, and Faer factorization/backsolve boundaries. The Rust quick start is
also corrected for the current compiler facade and source syntax.

## 0.1.0a8 — unified authoring and explicit numerical execution

[Eqiora 0.1.0a8](https://github.com/nkiyohara/eqiora/releases/tag/v0.1.0a8) expands source and Python modeling through `eqiora.Module`,
with typed arrays, records, enums, explicit derivatives, events, and clocks.
Projects gain exact local/Git dependency locks and offline vendoring, and the
language-server preview provides diagnostics, formatting, and navigation.

Coupled scalar Q1 equations and fixed-reference FSI share equation-derived
region assembly with exact Field ownership. Solver requests explicitly choose
an objective or a complete algorithm, preconditioner, reduction, and provider.
Typed observables, parameter batches, and bounded JAX `vmap` composition extend
analysis. Smooth ODE functionals add terminal evaluation and accepted-step
Simpson integration independent of output cadence. Steady scalar Laws retain
outward flux and source through Model replay.

These are bounded alpha capabilities. Laws exclude storage and moving volumes;
trajectory functionals exclude events, resets, derivatives, and spatial-time
composition. Convex-polyhedral Geometry supports correspondence to supplied
tetrahedral meshes, without adding a tetrahedral mesher or new PDE/FSI execution.
General equation-driven numerical admission and arbitrary multi-region
composition remain work for the subsequent 0.1.0 release.

When upgrading, replace displaced Python `Source`/builder paths with
`eqiora.Module`, update Model/Component signatures, and use explicit symbolic
`equation(lhs, rhs)` calls. Recompile models and regenerate saved execution
artifacts and package locks; obsolete pre-1.0 decoders and aliases are removed.

## 0.1.0a7 — equation authoring and reusable numerical setup

[Eqiora 0.1.0a7](https://github.com/nkiyohara/eqiora/releases/tag/v0.1.0a7)
adds natural equation authoring to Python `Source` and infers dimensions for
model-local aliases. Scalar conservation handling extends across Cartesian
1D–3D models, and elasticity calculations share continuum and material operations.
Runs prepare reusable execution data and Faer factorizations once, and
cancellation makes the last accepted State available.

Mesh generation uses `MeshPlan`. Physics-specific dimension aliases and the
Marimo/Jupyter example paths were removed; use derived dimensions and the
maintained Colab examples when migrating.

## 0.1.0a6 — scalar properties and local file interchange

[Eqiora 0.1.0a6](https://github.com/nkiyohara/eqiora/releases/tag/v0.1.0a6)
adds scalar property bindings, affine coefficients, authored scalar primal
Formulations, and directional Stokes correspondence. Language additions include
`math.pi`, typed model-local `let`, and derived-dimension aliases. Equivalent
additive equation orientations produce the same residual.

Plans, Results, and Trajectories gain atomic local file I/O. Rust adds a common
transient `RunRequest`. The cylinder examples use finer presentation meshes
and clearer startup animations, and clean Colab Gmsh startup was fixed.

## 0.1.0a5 — inspect formulations and save execution artifacts

[Eqiora 0.1.0a5](https://github.com/nkiyohara/eqiora/releases/tag/v0.1.0a5)
lets users inspect the effective Formulation selected for a Plan and save
resolved Plans, restartable States, Trajectories, and Results. Loading checks
that the supplied upstream objects match the saved artifact.

Static scalar, elasticity, and Stokes runs return the common Result. The optional
`eqiora.View` viewer displays 2D Geometry, Mesh, selections, and scalar Fields
from Python. Package compilation now binds a public Component to supplied
Geometry and Parameters; older v1 compilation records are no longer decoded.

## 0.1.0a4 — common run workflow and cylinder startup

[Eqiora 0.1.0a4](https://github.com/nkiyohara/eqiora/releases/tag/v0.1.0a4)
uses `.eqi → eqiora.compile() → eqiora.resolve() → eqiora.run()` with Geometry,
Mesh, and numerical settings supplied by the application. It adds a Colab
walkthrough of the first steps of transient flow around a cylinder. The
packaged DC-drive example also runs in Studio.

## 0.1.0a3 — Gmsh meshing

[Eqiora 0.1.0a3](https://github.com/nkiyohara/eqiora/releases/tag/v0.1.0a3)
uses Gmsh 4.15.2 for the exact-cylinder Python workflow and updates its pressure
output and Gallery image.

## 0.1.0a2 — second public alpha

[Eqiora 0.1.0a2](https://github.com/nkiyohara/eqiora/releases/tag/v0.1.0a2)
expands the published Python, CLI, MCP, and Gallery interfaces. See the
[capabilities](/capabilities/) for the available problem classes and environments.

## 0.1.0a1 — first public alpha

[Eqiora 0.1.0a1](https://github.com/nkiyohara/eqiora/releases/tag/v0.1.0a1)
publishes the first Python package and its installation instructions. Each
linked release retains its original downloads and detailed release notes.
