Contributions are welcome. Small changes with one clear purpose are the easiest to review.

## Before opening a change

1. Read the <ExactSourceLink path="CONTRIBUTING.md" kind="blob">contribution guide</ExactSourceLink>.
2. Check the [architecture overview](/contributing/architecture/) and <ExactSourceLink path="docs/glossary.md" kind="blob">glossary</ExactSourceLink>.
3. Search existing issues and RFCs before introducing a public concept.
4. Limit each change to one capability that can be verified and reviewed on its own, and build on existing contracts instead of re-implementing them.

New public semantics, wire formats, stable interfaces, dependency-layer exceptions, numerical contracts, or governance changes require the <ExactSourceLink path="rfcs/README.md" kind="blob">RFC process</ExactSourceLink>.

The <ExactSourceLink path="crates/eqiora/examples/quickstart.rs" kind="blob">Rust quickstart</ExactSourceLink>
is a small complete facade example. The <ExactSourceLink path="examples/README.md" kind="blob">source example index</ExactSourceLink>
points to focused modeling and execution paths.
