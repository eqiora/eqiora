## Problem and accuracy

Both tools solve on the unit cube, with coordinates in metres:

$$
-\Delta u=3\pi^2\sin(\pi x)\sin(\pi y)\sin(\pi z),\qquad
u=0\text{ on every face}.
$$

The exact dimensionless solution is the product of the three sine factors.
Both use hexahedral Q1 elements, binary64 arithmetic and two-point tensor
Gauss integration. The actual FEniCSx rule, vertex-to-DOF correspondence and
six essential faces are checked. Eqiora uses its ordinary installed Python
compile, GeometryGraph cuboid, resolve and run APIs.

Both use zero-start BiCGStab with identity preconditioning, relative tolerance
`1e-12`, absolute tolerance `1e-14` and a 10,000-iteration limit. Every solve
took one iteration: this load is a single discrete eigenmode, so it does not
test general Krylov convergence. Each accepted result passes its true-residual
target and the existing independent analytic Q1 error allowance.

Continuous L2 errors are norms over the physical cube, with units m³ᐟ². The
refinement orders are approximately 2.00004 and 1.99973 in both tools.
Agreement between the tools is not the accuracy oracle.

| N / tool | Continuous L2 error |
|---|---:|
| 4 / Eqiora | 0.02298303 |
| 4 / FEniCSx | 0.02298303 |
| 8 / Eqiora | 0.005745602 |
| 8 / FEniCSx | 0.005745602 |
| 16 / Eqiora | 0.001436674 |

The <ExactSourceLink path="verify/numerics/cartesian-poisson-3d-fem-fvm/references/README.md" kind="blob">independent derivation</ExactSourceLink>
and its existing tolerance are unchanged. At the finest level both tools have
4,913 total and 3,375 free coefficients. Eqiora eliminates essential values;
FEniCSx retains identity rows. Zero boundary data and initial values give the
same effective free problem.

## Ordinary execution

Each row summarizes seven uninstrumented calls after two warmups. A cold call
and one separate diagnostic precede those warmups. The seven calls describe
within-process spread, not seven independent process repetitions. One fresh
child and JIT directory are used per tool and mesh; tool order alternates by
level. There was no repeated campaign or selection of faster attempts.

Execution includes fresh assembly, zero-start accepted solve and primary field
return, retaining only mesh and model/forms. No previous matrix, factorization,
preconditioner or Result is supplied for reuse. Accuracy integration, output
inspection, protocol checks, Result destruction and writes are outside the clock.
Median and median absolute deviation (MAD) below are milliseconds.

The measurement record retains every wall and process-CPU sample, range and

Mesh and preparation are single cold observations. Eqiora's mesh clock includes
GeometryGraph construction and geometry checks; preparation includes compile
and resolve. FEniCSx mesh creation and function-space/form preparation are
separate, with form compilation in a fresh JIT cache. Preparation wall time
includes compiler-child work; process CPU excludes that child CPU. Imports are

## Separate native diagnostics

At 16 cells per axis, the extra Eqiora diagnostic recorded 467.107 ms in scalar
finalization and 0.873 ms in linear solve. FEniCSx recorded 24.229 ms in assembly
and 0.742 ms in its linear-solve bracket. These are different tool-native
boundaries, not phase speed ratios or a partition of the unprofiled medians.

Eqiora scalar finalization includes numerical preparation, representability
checks and canonical-system construction, excluding earlier mapping work.
FEniCSx assembly includes allocation, assembly, lifting, ghost accumulation and
boundary conditions. Its linear bracket includes KSP setup, solve, true-residual
acceptance and policy/summary queries. Full phase inventories are retained.
Eqiora also recorded 383.645 ms of solve self time; this observation alone does
not attribute that time to a particular operation.

## Environment and reproduction

This uses an optimized Eqiora **development wheel**, version `0.1.5`, built from
an sdist with Rust 1.89, fat LTO and the repository's package-specific optimization
overrides. It is not a new published release or a complete distribution-profile
acceptance. FEniCSx uses DOLFINx/Basix 0.11, PETSc 3.25.6 and the checked-in lock.
Each child uses one CPU, one thread per library and one rank, with GPU hidden.

The worker ran on logical CPU 8 and its sibling was CPU 40; the supervisor ran
on CPU 9, on another physical core. Monitoring covered 21.636 seconds. CPU 40
was 100% busy, and the supervisor's sibling was 96.58% busy. Governor, boost and
topology settings matched before and after; no host settings were changed and
no utilization cutoff was applied.
