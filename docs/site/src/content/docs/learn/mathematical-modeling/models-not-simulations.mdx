## How long until a warm object cools?

Place a warm metal bead in a room and measure its temperature. Will it lose the
same number of degrees every minute? Or will cooling slow as it approaches room
temperature? Our first model predicts the second behavior: after each equal time
interval, the **temperature difference** shrinks by the same fraction.

This question will connect the whole path. We first describe the bead with one
number, then ask what changes when a slab needs a temperature at every point.
The [heat-transfer path](/learn/heat-transfer/) develops that spatial model;
[numerical simulation](/learn/numerical-simulation/) asks how accurately we
solve it. You can start in either subject and return here for a particular idea.

## Decide what the system contains

Draw an imaginary boundary around the bead. Energy leaves it and enters the
room. The room is treated as a reservoir with fixed temperature $T_\infty$.
Assume the bead has one uniform temperature $T(t)$, constant heat capacity
$C$ in joules per kelvin, and a constant thermal conductance $G$ to the room in
watts per kelvin. We neglect internal heating and changes of phase.

```text
             system boundary
          ┌──────────────────┐
          │ bead: C, T(t)    │ ── Pout = G(T − T∞) ──> room at T∞
          └──────────────────┘
```

*Conceptual energy-flow diagram. The arrow defines positive outward power;
if the bead is colder than the room, the signed power is negative.*

Energy balance gives $C\,\mathrm{d}T/\mathrm{d}t=-P_\mathrm{out}$.
Substitution yields

$$
C\frac{\mathrm{d}T}{\mathrm{d}t}+G(T-T_\infty)=0.
$$

The balance and the transfer law have different jobs: energy conservation
accounts for the change, while $G(T-T_\infty)$ describes the exchange we chose.
The ODE chapter will derive its solution. For now, check the signs: a hotter
bead has positive outward power and a negative temperature derivative.

For $T_0\ne T_\infty$, define $x=(T-T_\infty)/(T_0-T_\infty)$ and $k=G/C$.
The relation becomes $\dot x+kx=0$, with $x(0)=1$. Thus the small source example
below is also a normalized cooling model. Its dimensionless state is a ratio of
temperature differences, not temperature itself.

## Make a prediction before compiling

Take illustrative values $C=10\,\mathrm{J/K}$ and $G=0.1\,\mathrm{W/K}$.
At a temperature difference of $40\,\mathrm K$, the outward power is
$4\,\mathrm W$ and the initial cooling rate is $-0.4\,\mathrm{K/s}$. At half
that difference, the cooling rate is half as large. These are algebraic
consequences of our assumptions; no computer output is needed to obtain them.

The time scale $C/G=100\,\mathrm s$ compares storage with exchange. A bead
with twice the heat capacity and the same conductance responds twice as slowly.
The executable source uses $k=1\,\mathrm{s}^{-1}$ for a shorter experiment;
it has the same normalized mathematical structure.

## Why this distinction matters

A simulation is one way to investigate a model. It is not the model itself.
Keeping the two separate lets us ask two different questions:

1. **What mathematical statement follows from our assumptions?**
2. **How will a computer approximate and execute that statement?**

If those questions are mixed, changing a time step can appear to change the
physical meaning. In Eqiora, the boundary is explicit:

- a **Model** names quantities and states typed relations;
- a **Realization** selects numerical methods and execution policy;
- a **Run** applies a realization to state and inputs; and
- an **Observation** projects a result into values intended for interpretation.

## Learning outcomes

After this chapter, you should be able to:

- classify a statement as model meaning, realization policy, run input, or observation;
- explain why an initial value can belong to a model while an output time does not;
- compile a readable `.eqi` model without choosing a solver; and
- diagnose a solver choice that has leaked into model source.

## From phenomenon to relation

Suppose a dimensionless quantity $x$ decreases at a rate proportional to its
current value. We choose these assumptions:

- $x$ is the only changing quantity;
- the proportionality factor $k$ is constant and has inverse-time dimension;
- time is continuous; and
- the initial value of $x$ is one.

Those assumptions produce the residual relation

$$
\frac{\mathrm{d}x}{\mathrm{d}t} + kx = 0.
$$

Writing the relation as a residual equal to zero states mathematical meaning
without naming an integration method, tolerance, output schedule, processor,
or file format.

The declaration says that `x` is dimensionless and initially one, `rate` has
inverse-seconds dimension, and `flow` is a continuous relation. It does not say
which integrator to use or when to record output.

With the [package from Get started](/get-started/), compile the source from
Python without resolving or running it:

```python
from pathlib import Path

import eqiora

source = Path("decay.eqi").read_text(encoding="utf-8")
model = eqiora.compile(source=source, filename="decay.eqi")
print(model.field_ids)
```

Successful compilation establishes that the source is accepted by the current
language and semantic checker. It does not establish that the assumptions fit
a particular physical system.

## What belongs on each side

| Decision | Boundary | Reason |
| --- | --- | --- |
| $x(0)=1$ | Model | It is part of the mathematical initial-value problem. |
| $k$ has dimension $1/\mathrm{s}$ | Model | It makes the relation dimensionally meaningful. |
| Adaptive versus fixed stepping | Realization | It selects an approximation policy. |
| Stop at $t=2\,\mathrm{s}$ | Run | It is a request for one execution. |
| Record $x$ at selected times | Run / Observation | It chooses what one execution returns and exposes. |
| Plot color and line width | Presentation | They do not change the mathematical problem. |

Several numerical methods can solve the same model. Choose a method when
you are ready to run it; the equations above stay the same.

## Read the result

The printed field identifiers tell you which unknowns the compiler found.
Later, an observation will select values of those fields from a completed run.
The cooling rate and initial temperature determine the trajectory; choosing
which times to inspect determines the view you take of it.

## Deliberate failure: a method inside the model

This mutation tries to name a numerical stepping policy as though it were a
model quantity:

```eqiora
model decay() {
  state x: 1;
  initial { x = 1; }
  parameter rate: 1 / s = 1;
  relation flow {
    derivative(x) + euler_step * rate * x = 0;
  }
}
```

`euler_step` is undeclared, so compilation must fail. Declaring it merely to
silence the error would still encode a numerical choice in the wrong layer.
The repair is to restore the method-neutral residual and choose stepping only
when constructing a Realization.

## When should the model change?

A single temperature is useful when internal temperature differences relax much
faster than exchange with the room. If the surface cools long before the core,
reducing a solver tolerance cannot recover the missing spatial field. Likewise,
a room that warms appreciably must become part of the system rather than remain
a fixed reservoir. These are changes in the physical model.

A measured departure from exponential cooling invites several explanations:
temperature-dependent properties, a changing environment, measurement delay,
or numerical error. Separate them by asking what can be checked independently.
For example, compare the computed trajectory to the analytic solution before
using a disagreement with a thermometer to question the transfer law.

For the mathematical modeling of first-order physical systems, see the MIT
notes listed below. Our bead and parameter choices are an original illustrative
example, not measured material data.
