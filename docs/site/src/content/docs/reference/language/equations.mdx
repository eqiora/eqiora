## Simultaneous relations

```eqi
relation ohm { voltage = resistance * current; }
```

A relation constrains quantities. It is not an assignment or a sequence of commands.
Both sides must have matching dimensions and shapes. A relation may contain several
equations, all of which hold simultaneously. Use `on body` for a spatial relation
and `at tick` for a relation activated by a periodic clock.

## Continuous state and initial equations

<Code code={decay} lang="eqiora" title="decay.eqi" />

`derivative(x)` denotes the time derivative of a continuous state. Here the model
has the solution $x(t)=\exp(-t)$ with the default rate of 1/s.
`initial` supplies the mathematical initial equation; a solver's initial guess
or time step does not replace it.

The [ODE lesson](/learn/mathematical-modeling/ordinary-differential-equations/)
continues through `State.initial(plan)` and execution. To continue an existing run,
use its accepted State rather than reinitializing the model at each output time.

## Conservation laws and weak forms

A `law` gives storage, outward flux, and source terms. A steady law has no storage
term. The following complete component uses Fourier conduction and four fixed
boundary temperatures:

<Code code={heat.slice(0, heat.indexOf('/// Heat storage'))} lang="eqiora" title="HeatedBody — steady conduction" />

Read its flux as $\mathbf q=-k\nabla T$ and source as volumetric heating.
The local steady balance is $\nabla\cdot\mathbf q=Q$.
`form weak_heat for heat_balance` attaches a weak form to that physical law.
`test w: 1 for temperature zero_on ...` associates a test field with temperature
and makes it vanish on the prescribed-temperature boundaries. `integrate` and
`dot` express the resulting integral equation.

For time-dependent storage, the same source provides:

<Code code={heat.slice(heat.indexOf('/// Heat storage'))} lang="eqiora" title="TransientHeatedBody — heat storage and conduction" />

The balance is now $\partial_t(cT)+\nabla\cdot\mathbf q=Q$ with constant
volumetric heat capacity $c$. The initial field is 300 K everywhere.
Follow [the thermal model walkthrough](/learn/heat-transfer/heated-body-in-eqiora/)
for package construction and execution, or
[weak forms and finite elements](/learn/numerical-simulation/weak-forms-and-finite-elements/)
for the derivation.

### Common spatial operators

| Expression | Meaning |
|---|---|
| `grad(temperature)` | Spatial temperature gradient |
| `div(velocity)` | Divergence of a velocity field |
| `symmetric_part(grad(displacement))` | Infinitesimal strain tensor |
| `trace(temperature)` | Temperature restricted to the relation's boundary |
| `normal(stress)` | Stress contracted with the parent-outward normal, giving traction |
| `isotropic_lift(pressure)` | Pressure times the identity tensor |
| `dot(a, b)` | Inner product of compatible vectors |

The support and tensor shapes must match the operation. See
[continuum components](/reference/standard-packages/continuum/) for stress and
boundary examples.

## Periodic state

<Code code={clocked} lang="eqiora" title="clocked.eqi" />

The clock period is exactly 1/10 second, with phase zero. `pre(memory)` is the
value before a tick; `next(memory)` is the candidate updated value. The first tick
advances memory from 0 to 1. The update's equations are simultaneous.

`pre` and `next` require a state on that exact clock; use `derivative` for continuous
state. Equal clock periods do not make independently declared clocks interchangeable.
[Sampled controls](/reference/standard-packages/controls/) provides reusable delay
and integration components and an executable project.

## Inequalities and complementarity

```eqi
model Contact(parameter load: N = 0) {
  variable gap: m;
  variable force: N;
  relation contact {
    2[N/m] * gap - force = load;
    complementarity(0[m] <= gap, force >= 0[N]);
    inequality(gap <= 4[m]);
  }
}
```

The complementarity condition requires nonnegative gap and force with at least
one equal to zero. A positive gap therefore has zero contact force; a positive
contact force has zero gap. The inequality adds an upper bound on the gap.

`inequality` uses non-strict `<=` or `>=` between compatible real scalars.
`complementarity` takes two explicit nonnegativity predicates; its two operands
may have different dimensions, as above, but share support.

Execution supports finite nonspatial affine active sets. The Plan specifies
constraint tolerances in coherent SI units and a bound on branch enumeration.
This formulation adds no implicit penalty or smoothing. Spatial contact and
friction require additional modeling and solver capabilities.
