# Repeated-Run baseline after ordinary IDA integration (2026-10-24)

Four alternating comparisons of the accepted #1698 wheel show a cylinder
median of 6.008260 s against 5.586206 s for the earlier implementation.
The 7.56% gap remains open under #802. All ten physical cylinder outputs match
exactly in every pair. This advances the measurement and cost-prioritization
work of #727; it does not establish a portable non-regression bound or complete
either issue.

## Inputs and environment

The workloads and ordinary installed `eqiora.run` timing boundary are those of
[the initial baseline](2026-10-24-repeated-runs.md#inputs). The cylinder retains
the same a7 steady seed, mesh, ten Backward Euler steps and numerical controls.
Unlike the earlier a7 comparison, this comparison uses the current authoring
route for both revisions. Output inspection, import, compilation, mesh creation
and initial binding remain outside the measured Run call. Each call creates a
fresh Run from the same immutable Plan and State.

Both installations ran on dide1/didelx01, AMD Threadripper PRO 5995WX, Linux
6.8.0-94/glibc 2.35, affinity CPU 16. The CPU was not exclusively reserved.
CPython 3.13.14, NumPy 2.5.2 and Gmsh 4.15.2 were identical; OMP, OpenBLAS, MKL
and Rayon thread limits were one. No GPU was used.

Reference source: `204a289d88f3d782d94190d47e15ffd7cb2df5d7`, wheel SHA256
`8ab31a6dbc88ddf1d131fdd0268b0cec536a6787d6e3085d6b12404c5a3bac5c`.
Candidate source: `8843cf93909248ea092f1a866003a1cc6a088fa2`, wheel SHA256
`a538132eb1ec908b0f0679fd95c84471a26e23fb54342f7d3de9ccea0517b167`.
The reference used Rust 1.98 and manylinux 2.35; the candidate used Rust 1.89,
manylinux 2.17 and the five declared package size profiles. Build differences
prevent attribution of the remaining gap solely to source changes or IDA.
The cylinder itself still uses Backward Euler, not the IDA provider.

The accepted candidate wheel is 16,707,218 bytes; its native expanded member is
40,225,889 bytes. The unchanged distribution bounds and every required installed
profile passed `interfaces.python-distribution-candidate` before acceptance.

## Measurements

Each of four alternating pairs includes a cold call, two untimed warmups and
seven samples per workload. Cylinder samples each contain one Run; decay samples
each average 100 calls. The table pools the 28 sample means for each installation.
Separate profiles are excluded from these timing statistics.

| Workload | Reference median (range) | Candidate median (range) |
| --- | --- | --- |
| Cylinder | 5.586206 s (5.488717–5.710354) | 6.008260 s (5.929102–6.194368) |
| Decay | 204.288 µs (193.885–217.567) | 205.174 µs (196.778–220.998) |

Every pair has exact equality of velocity vertex values, velocity cell values
and pressure vertex values at all ten output times. The independent decay
reference is exp(-t), with the unchanged 1e-8 absolute probe bound. Equality on
these workloads does not establish general numerical equivalence.

The [measurement data](2026-10-24-ida-run-data.json) retains raw wall/process
samples, cold times, loads, installation and input hashes, four complete field
difference reports, and separate profile phase trees. No confidence interval,
shared-host CI threshold or cross-environment claim is inferred.

## Dominant costs and next work

The separate candidate cylinder Profile totals 6.457995 s. These are exclusive
self-time sums, not percentages of the unprofiled median:

| Work | Seconds |
| --- | ---: |
| Local assembly evaluation | 1.541820 |
| Scatter update, excluding local evaluation | 0.608948 |
| Discretization preparation, excluding assembly preparation | 0.966764 |
| Assembly preparation | 0.196068 |
| Numeric LU | 1.045273 |
| Unpartitioned time-step work | 0.903910 |

The earlier candidate's cylinder median was 11.550884 s. Profiling located most
of that regression in scatter. A cloned immutable structure identity repeatedly
compared its shared encoding bytes under Rust 1.89. The correction explicitly
accepts identical buffer storage before a full byte comparison, while retaining
digest equality and full comparisons for independently owned buffers. Forged
same-digest/different-byte and shared-byte/different-digest identities still
reject. Both registered sparse-LU reuse cases pass. No cache or relaxed reuse
admission was introduced.

A numerics-only optimization-level-3 diagnostic did not improve scatter and
exceeded both existing wheel-size bounds, so it was not adopted. The final
correction removes the major regression but does not erase the remaining 7.56%
gap. Prioritize local residual/matrix assembly, preparation, then numeric LU.
Symbolic LU already occurs once per Run; another symbolic cache is not the first
optimization. Memory/scaling, failed-step cost and conventional CFD comparisons
remain unmeasured here.

## Reproduction

Use the existing [repository harness](../../tools/benchmarks/repeated_execution/run.py)
and the commands in the initial report, with `--edition candidate` for both
installations and the revisions/wheels above. Alternate four pairs on the same
CPU and retain the default two warmups/seven samples; use 100 calls per decay
sample. Run `--profile` separately. The measured driver SHA256 is
`97629d763e79fdb6fa99b399addabdfa3122de2a103d5aeb9e0b39807ca1c2b2`;
fixture SHA256 is
`f0734737549c8a7fefff14dd1c8b4be3ca8f094ce4ac5729b38321f84b493d88`.
The operator must install the recorded wheel and authenticate its source/build;
the harness's declared revision alone is not a build-provenance proof.
