# Cartesian polynomial curl and oriented traces

This case independently checks the real explicit-coordinate polynomial profile through
source compilation, exact Model replay and native point evaluation. One interior curl
observation also traverses the ordinary algebraic Plan, Run and Result observation path.
The algebraic solve retains an unrelated scalar anchor; it is not a spatial PDE solve.
The spatial arithmetic profile admits addition/subtraction, multiplication, nonnegative
integer powers and polynomial pure component maps, not division or nonpolynomial calls.

The [independent component derivation](references/README.md) defines the expected
values and sign conventions. [Acceptance](expected/README.md) uses exact binary64
values for these small integer polynomial fixtures. Wrong face position, foreign
coordinate factors, missing axes and unknown Field reconstruction probe admission.

Complex spatial execution, arbitrary boundary charts, unknown vector Field
reconstruction, compatible finite-element spaces, weak Formulation correspondence
and Maxwell execution are outside this claim. Compiler and pure-calculus product
tests separately check 2D reductions and complex typing; they are not evidence of
complex spatial execution.

Run `cargo run -p eqiora-verify -- run --case language.oriented-vector-calculus`.
